# 日本語の文書規約

このリポジトリの日本語による説明、設計記録、Issue、PR、公開報告は、[日本語の記事を執筆・推敲するためのルール](https://imoz.jp/humanizer.ja.txt)を参照して編集する。コード識別子、CLIの引数、設定キー、外部文書の正式名称は変更しない。英語の既存文書を一律に日本語化する必要もない。

## 記述と検証の原則

1. 読者が何を実行・判断できるようになるかを決め、結論と主要な根拠を先に書く。見出しは本文の具体的な内容に合わせる。
2. **実装済み、模擬データで動作確認済み、実モデルで精度評価済み、将来の計画**を区別する。模擬LLM応答を使ったテストを「実モデルの精度検証」と呼ばない。
3. 論文の結果と、本プロジェクトの実装・評価結果を分ける。数値には対象、条件、出典を添える。確認できない事実は未確認と書く。
4. 書き換える際は、処理の主体、条件、操作順序、否定の範囲、指示の強さを保つ。短くするために仕様の意味を変えない。
5. 重複した結論や不要な注意を削る。例は、入力・操作・結果が分かるものだけを残す。主張の範囲に必要な注意は該当箇所の近くに置く。
6. 表の列、分類名、単位、年月日を揃える。表だけを読む人にも対象と条件が分かるようにする。
7. 公開前に本文だけを通読し、リンク、参照先、コマンド、テスト結果を照合する。変更前後で主張の強さや条件が変わっていないか確認し、文章上の変更と事実訂正を分けて記録する。

この規約は自動採点の基準ではない。文の長さ、箇条書きの数、語尾の繰り返しを機械的な合否条件にしない。意味を保ち、読者が一度で理解できるかを判断する。
