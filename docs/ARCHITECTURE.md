# Architecture and source of truth

## Responsibility boundaries

1. Ingest: UTF-8 document (current). PDF, OCR and connectors out of scope.
2. Domain definition: `domain_packs/<id>.json` owns versioned actions and human-review flag; `config/domain_registry.json` records priority, input hints, proposed sources, cross-links and guardrails. The CLI selects an explicit `--domain` or the configured default; registry hints and guardrails are not yet enforced by the extractor.
3. Prompt: generated by `ukl.build_prompt` using selected domain pack; source is explicitly untrusted data.
4. Model: optional local OpenAI-compatible endpoint, with defaults in `config/pipeline.json`; alternatively a saved JSON fixture.
5. Validation: accept only declared kinds/statuses/actions and exact quoted substrings. Reject malformed content, do not silently repair.
6. Provenance: source ID, full SHA-256, quote, offsets and count of matches. Same text might recur; flag such ambiguity for review.
7. Interchange: extraction JSON + graph node/edge JSON. Graph stores mentions, **not** causes, contradiction resolutions or verified identities.
8. Verification: GitHub Actions runs configuration checks, synthetic-fixture tests and Pages artifact checks. After deployment, the Pages workflow fetches the public HTML and manifest to verify the commit SHA and domain list. These checks do not measure model extraction accuracy. Labeled reference data and accuracy gates are still planned.

## Key distinctions

- `performed` vs `planned` vs `hypothetical` vs `negated` vs `reported` vs `uncertain` are separate states.
- Exact quote validation is syntactic, not semantic verification.
- Domain extension does **not** imply transfer of accuracy: every domain needs a gold test set and human review policy.
- Extraction is training-free *at application time*. The inference model itself is pretrained.
- Prospector is a trained traversal policy. `to_graph` is only graph interchange, not Prospector.

## Data authority

| Concern | Canonical | Derived |
| --- | --- | --- |
| Operations / review policy | `domain_packs/*.json` | System prompt |
| Domain ownership / source priority / crosslinks | `config/domain_registry.json` | Documentation and planned routing, not yet used by model |
| Runtime defaults | `config/pipeline.json` | CLI args unless overridden explicitly |
| Accepted record | `ukl.normalize` | JSON output |
| Graph representation | `ukl.to_graph` | Graph JSON output |
| Interface visual design | `KAFKA2306/design` | Future UI consumer |
| Reusable prompt assets | `KAFKA2306/prompt-vault` | Optional version-pinned adoption |

## Future interfaces (not yet implemented)

- `source -> spans -> extracted records -> entity resolution -> graph -> evidence-grounded retrieval`
- `domain_pack_version` and `source_sha256` allow later migration and audit. Future policy will pin model/prompt version, not currently captured.
- Multi-domain relations must require explicit source citations and distinguish source-based from inferred edges.
