# 入力文書と抽出結果の安全管理

この試作はローカルでの実験用です。認証、利用者ごとの権限設定、監査記録の保存、機密情報のマスキング、外部公開サービスとしての負荷対策は実装していません。

- 入力文書とモデルの返答は信頼しない。文書中の指示を実行しないようモデルに要求していますが、指示混入への耐性を検証したわけではありません。
- `ukl.py` は推論先のURLをループバック上のHTTPに制限します。外部APIへの送信を前提とした機能はありません。ただし、ローカルサーバー自身の設定や保存内容は別途確認が必要です。
- 実際の個人情報、顧客情報、医療情報、社内資料、認証情報をGitHubへ登録しない。テストには架空データを使用する。`.env`、`local_data/`、`results/` はGitの追跡対象から除外しています。
- 抽出結果の `source.quote` には入力文書の原文が残ります。共有前に内容を確認し、アクセス権のある保存先で管理してください。
- 製造、金融・投資、セキュリティ、キャリア、ソフトウェアの操作結果は人が確認する。`requires_review` は要確認の印を付ける設定で、承認機能ではありません。抽出結果だけを根拠に設備、取引、認証、本番環境を変更しません。
- 公開リポジトリのCIとPages公開は稼働しています。push protection、secret scanning、ブランチ保護、必須チェックがGitHub側で有効かは未確認です。利用可能な設定を確認し、検証が成功したことを権限保護の証明として扱わないでください。
