# 公開情報を集める手順

このプロジェクトは**情報源と候補URL**を蓄積します。論文本文、内部資料、個人の予定、抽出した全文は公開リポジトリに保存しません。

## 現在の仕組み

- `config/source_registry.json` は11分野に対応した公開情報源の登録先です。`sources`は所在地を確認済みの出典入口、`candidates`は**未審査**の発見候補で、どちらも記述内容の真偽を保証しません。
- `scripts/source_intake.py` は登録内容と分野ID・URL・重複を検査します。`--online`では、登録したAtomフィードからタイトル・URL・公開日付だけを取得します。本文や要約は保存しません。
- `.github/workflows/source-intake.yml` は毎週日曜21:15（日本時間）に候補を収集し、差分があった場合のみPRを作ります。**自動マージはしません**。GitHub ActionsからのPR作成が制限されている場合、ワークフローは失敗します。
- 現在のAtomフィードはllama.cpp、uv、FastAPI、VRChat Creator Companionの4件です。自動取得対象はローカルAI・ソフトウェア開発・ゲーム／VRの3分野で、全11分野の自動収集ではありません。2026年11月2日時点で、公式の個別リリース5件を未審査候補として登録しています。TSMCの2026年第3四半期決算など、公式の個別資料も情報源として追加しました。

## 人が審査する項目

候補のURL・分野・公開日付・既存登録との重複・利用許諾を確認します。候補タイトルが示す内容や影響を、本文未確認のまま事実として登録しません。候補の採用はPRレビュー後に行い、必要なら出典入口に移動するか、別の根拠データベースを使います。

## 手動での検査

```bash
python scripts/source_intake.py
python -m unittest discover -s tests -v
```

実際のネットワーク取得は`python scripts/source_intake.py --online`で実行します。このコマンドは`config/source_registry.json`へ候補を追記するため、実行後に差分を確認してください。

## セキュリティとデータ管理

登録フィードのホストは固定し、フィードから取得したURLも許可したホストに限定します。外部から取得した文字列は指示として実行しません。GitHub Actionsで取得するものは公開可能な書誌情報だけです。公開前にデータ元の規約を確認してください。個人情報や認証キーを登録する用途には使いません。
