# 抽出結果の評価方法

現状の自動テストは、11分野の架空例と人が作成した模擬LLM応答を使って、引用照合、操作名の許可判定、出力形式を確認します。GitHub Actionsではこれに加え、Pages用HTMLとJSONの整合性、および公開後のコミットSHAを検査します。

**実モデルを動かして正解データと比較した精度（適合率・再現率・F1）は未測定です。** GitHub Actionsの成功は、設定とプログラムが所定の検査を通過したことを示します。

## 実モデルを評価するときの項目

- 正解データと比べ、操作名、種類（`kind`）、状態（`status`）、主要な引数の適合率・再現率・F1を測る。
- 引用が原文に存在する割合と、その引用が抽出結果の意味を実際に支える割合を別に測る。後者は分野に詳しい評価者が確認する。
- 数字、単位、否定、予定と実施済みの取り違えを数える。
- 抽出を拒否した割合、判断を保留した割合、人手で修正した件数、処理時間、費用を記録する。
- モデルの版、分野定義の版、プロンプトの版、データの出所・利用条件・件数を記録する。

評価用文章は、資料の出所と公表時期を考慮して分割し、同じ例を学習・調整と評価に重複利用しない。LLMを使わない方法、共通の指示だけを与えたLLMと比較する。分野を追加した場合は、その分野で新たに測定する。

現在の検証コマンドは [`CONFIGURATION.md`](CONFIGURATION.md)、公開結果の検証手順は [`PAGES_VALIDATION.md`](PAGES_VALIDATION.md) に記載しています。実モデルの評価は、正解データを作成した後に実施します。
